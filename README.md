# Вариант 11. Анализатор игровых событий

**СТАРТОВЫЙ ПРОЕКТ ДЛЯ СТУДЕНТА**

**Покрываемые темы:** LINQ, PLINQ, Aggregate, Parallel, Stopwatch

## Условия зачёта

Выполнить 7 обязательных заданий. Дополнительные задания повышают оценку. Код должен собираться на .NET 9.
Не допускаются пустые `catch`, блокирующие ожидания в UI-потоке и небезопасное совместное изменение состояния.

## Обязательные задания
1. Создать модель игрового события.
2. Сгенерировать тестовые события с фиксированным seed.
3. Реализовать последовательную статистику через LINQ.
4. Реализовать эквивалентную статистику через PLINQ.
5. Сохранить порядок результатов там, где он требуется, используя AsOrdered или OrderBy.
6. Сравнить результаты LINQ и PLINQ на одинаковых данных.
7. Измерить производительность на нескольких размерах коллекции.

## Дополнительные задания
8. Добавить Aggregate с локальным аккумулятором.
9. Добавить стабильную сортировку с ThenBy.
10. Проверить пустую коллекцию и отсутствие событий нужного типа.

## Требования к сдаче

- Сохранить комментарии `TODO` и заменить их реализацией.
- Добавить отдельные классы для моделей и сервисов.
- Приложить 3–5 тестовых сценариев или пошаговую инструкцию проверки.
- Подготовить устное объяснение архитектуры и одного исправленного дефекта.
